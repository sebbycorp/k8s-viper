k8s-viper environment

Single-node k3s lab managed with Argo CD GitOps. This page is the full map of the environment: how it’s built, what’s deployed, how you reach every UI, and how day-2 changes flow.

k3s v1.32 Argo CD Vault OSS External Secrets Headlamp Traefik

Stored in this browser only. kubectl get nodes -o wide

1. Overview

k8s-viper is a powerhouse-style single-node Kubernetes box. Bootstrap once; everything after that is git → Argo CD.

Bootstrapscripts/bootstrap.sh (once / idempotent)

2. Architecture

Imperative install only for k3s + Argo + root app. Platform services are GitOps.

bootstrap.sh  →  k3s + Argo CD + root Application
                      ↓
              argocd/apps/*  (GitOps, auto-sync)
                      ↓
   platform/ingress | vault | external-secrets | headlamp | argocd-access
                      ↓
   Traefik :80/:443  +  NodePorts 30080 / 30443 / 30200
                      ↓
   apps/*  (your workloads later)
Hard rule: never commit secrets. Values live in Vault; git holds ExternalSecret paths only. Prefer PR → validate → merge over kubectl apply for platform desired state.

4.1 Auth commands

# Node IP
kubectl get nodes -o jsonpath='{.items[0].status.addresses[?(@.type=="InternalIP")].address}{"\n"}'

# Argo CD admin password (user: admin)
kubectl -n argocd get secret argocd-initial-admin-secret \
  -o jsonpath='{.data.password}' | base64 -d; echo

# Headlamp SA token (paste into login form)
kubectl -n headlamp create token headlamp --duration=12h

# Kubeconfig on the node
export KUBECONFIG=/etc/rancher/k3s/k3s.yaml

Argo UI uses a self-signed cert — accept the browser warning. Vault UI needs init + unseal first (see Secrets).

9. Bootstrap

Run on the target Linux node with outbound HTTPS.

git clone https://github.com/sebbycorp/k8s-viper.git
cd k8s-viper
sudo ./scripts/bootstrap.sh

Optional env

VariableDefaultMeaning
REPO_URLthis GitHub repoGitOps source for Argo
REPO_REVISIONmainBranch / tag / SHA
ARGOCD_VERSIONv3.5.0Upstream install manifest pin
INSTALL_K3S_SKIP0Set 1 if k3s already installed
 
sudo REPO_URL=https://github.com/YOU/k8s-viper.git \
     REPO_REVISION=main \
     ARGOCD_VERSION=v3.5.0 \
     ./scripts/bootstrap.sh

# Existing cluster:
sudo INSTALL_K3S_SKIP=1 ./scripts/bootstrap.sh

Bootstrap installs k3s, Argo CD, AppProject seed, and the root Application. Re-runs are safe.

10. Day-2 GitOps

  1. Edit manifests or Helm values on a branch.
  2. Open a PR — CI runs scripts/validate.sh (no cluster credentials).
  3. Merge to main.
  4. Argo CD auto-syncs (prune + self-heal on platform apps).
./scripts/validate.sh
kubectl -n argocd get applications

11. Secrets (Vault + ESO)

After Argo syncs platform-vault and platform-external-secrets, init and unseal Vault once, then wire Kubernetes auth for ESO. Full runbook: docs/vault-eso-setup.md. 

# Wait for pod
kubectl -n vault get pods

# Init once — store unseal keys + root token offline
kubectl -n vault exec -it vault-0 -- vault operator init -key-shares=5 -key-threshold=3

# Unseal (3 of 5) after every pod restart until automated
kubectl -n vault exec -it vault-0 -- vault operator unseal

# UI (after unseal)
# http://<node-ip>:30200/
Never commit unseal keys, root tokens, or raw secret values. Example store only: platform/external-secrets/cluster-secret-store-vault.example.yaml.

14. Security notes

  • v1 lab assumes private LAN access to NodePorts and Traefik.
  • Headlamp chart binds cluster-admin for full lab visibility — tighten for multi-user.
  • Leave config.unsafeUseServiceAccountToken off unless behind a real auth proxy.
  • Argo CD serves a self-signed TLS cert on the NodePort.
  • Vault tlsDisable: true in chart values — fine for lab, not production.
  • No OIDC / SSO in v1.
